# strip/strip

**Does** — The tab strip page (`index.html`, `strip.css`, `strip.ts`): renders tabs from the main process's state, and when the tab bar is hidden slides it in and out over a 12px gutter.

**Why it exists** — Our own draggable title bar, so Onshape's page is never modified. Making Onshape's header draggable would need CSS in its page and leaves nothing to drag in a narrow window.

**Talks to** — `window.zenshape` from `strip/preload.ts`.

**Gotchas**
- The body is the drag region (`-webkit-app-region: drag`); tabs and buttons opt out. `#drag-gap` keeps ≥48px of drag space however narrow the window is.
- Split: the pair renders as one `.group` (CSS-drawn arrangement icon + two halves). Icon click swaps (after a 250ms double-click wait), double-click rotates. Locked tabs show a small lock icon.
- Tabs select on release unless dragged, so dragging a third tab doesn't hide the split it's dropped on. Dragging onto the middle 50% of a tab splits with it; near its edges reorders; below the strip sends `drag-page`/`drop-page` with window coordinates.
- Hidden tab bar (`body.collapsed`): the gutter is the root's own background (`html.collapsed`), painted `--gutter-color` at `--gutter-h`, both set from state (`gutterColor`, `gutterHeight`) so the page layout and the window controls' color can't drift from it. The color follows `state.gutter` (also on `html[data-gutter]`): Onshape's top-bar color `#1c1c1c` while that bar is at the top of the page (`bar`), white over a drawing's toolbar in zen mode (`drawing`), and zen's gray `#333` on any other document in zen mode, where the top bar is hidden (`zen`). The height is 12px on macOS, taller on Windows and Linux to hold the window controls (`docs/tab-views.md`). The strip reports the controls overlay's height (`controls-height`) whenever it changes: Windows' real height reaches main only that way. It must be the root's: with no root background, the body's is painted on the canvas under everything, and the gutter showed over the slid-in strip; the strip sits translated above it; `peeked` slides it down. Hovering the gutter sends `peek`, leaving sends `unpeek` after 300ms (not while a tab is held or renamed). Right-click on empty space or the Z sends `strip-menu` (off macOS that menu holds the app menu); tabs stop propagation for their own menu. The Z's click toggles zen; its tooltip is "Zen Mode (⌃⌘Z)" on macOS and "Zen Mode — right-click for menu" elsewhere (`state.controls`).
- The Update available button (left of the Z) shows while `state.update` is set and sends `open-update`.
- Splash mode (`#splash`): the Z logo, version and the disclaimer from `src/disclaimer.ts`; shown while `state.splash` is set, fades out when it clears; a click or Esc/Enter sends `dismiss-splash`. With `splash: 'saved-sign-in'` it shows the Saved Sign-in page instead: email (filled from `state.savedSignIn.email` unless typed over), password (with a login saved, a fixed mask, `SAVED_PASSWORD_MASK`, so it looks filled; the first edit drops the whole mask (`beforeinput`), emptied it gets the mask back on blur, and the mask or anything still holding a mask dot sends null, meaning the saved one, so a partly edited mask is never saved; forgetting the login with the page open clears it) and one button, Sign in, which Return also presses. Sign in stays disabled until there's an email and a password typed or saved (`canSignIn`): with nothing saved, both fields start empty and it does nothing until both are filled. With a login saved, Sign in takes focus once it's enabled (the saved email arrives a moment after the page shows), so Return works, but only if no field had focus when the page opened, and only while nothing in the form has focus: a field focused at any point (including one that kept focus across a hide and reopen), or the page hiding, ends that. After Sign in, the password field goes back to the mask when a login is saved. A password containing `•` shows "Passwords containing • can't be saved here." and Sign in stays disabled until it's changed. Clicks don't dismiss it; Esc does, showing Onshape's page. Sign in sends `sign-in` and clears the password field; the saved password never comes to this page. `savedSignInError` shows a refusal under the fields. Beside the fields (one column under 680px), "One click on Sign in:" lists the four steps with inline SVG icons (floppy disk, envelope, padlock, check), all blue outlines, each an `li[data-step]`; during a run `state.signInRun` marks them `done` or `stopped`, with the reason under the list, and the button is disabled.
- The splash's background is `--bar` at 99%, never fully opaque. On Windows, Chromium treats a page an opaque view fully covers as hidden: no frames, and keys sent to it are dropped (text from `insertText` still arrives). The Sign in run types into Onshape's page and presses Return while the splash covers it, so a solid background broke Continue (seen 2026-11-25; reproduced in a scratch Electron 45 run, where 99% fixed it). `test/splash-see-through.test.ts` holds it.
- Overlay mode (`#overlay`): draws the drop preview box from `state.dropPreview`.
- The Z button (far right, or left of the window controls) toggles zen; blue normally, white in zen.
- Divider mode (`#divider`): the page renders only a resize handle and reports the pointer as a ratio of its own size once main has stretched it.
- Rename: the tab's name becomes a text field. Enter or clicking away saves, Esc cancels. Re-renders wait while it's open so typing isn't lost.
- Drag to reorder: press a tab, move 4px, and it follows the pointer while a blue bar marks where it will land; only same-group positions count. Renders are held while a tab is pressed, since selecting it triggers a re-render that would replace the node being dragged. Leaving the 36px strip counts as letting go.
- Back / forward buttons sit right after the traffic-light inset, disabled when the active tab has no history that way.
- The traffic-light inset (`#lights`) is 86px on macOS: the buttons plus a ~20px gap before the first tab. In macOS full screen, and on Windows and Linux (`state.controls === 'overlay'`, `body.overlay-controls`), it's an 8px margin.
- Windows and Linux: the window's own controls overlay the strip's right end. `body.overlay-controls` pads the right by what `env(titlebar-area-x/width)` leaves of the width, so the Update button and the Z sit left of them.
- Colors are sampled from Onshape's dark header (`#1c1c1c`).
- Dev loads it from Vite's dev server (hot reload); packaged loads `.vite/renderer/strip/index.html`.
